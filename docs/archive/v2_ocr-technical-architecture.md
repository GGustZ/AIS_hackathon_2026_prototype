# สถาปัตยกรรมเทคนิค

ชื่อทำงาน: **ตรวจรู้** (ยังไม่ล็อก)

---

## หลักการออกแบบข้อเดียวที่ทุกอย่างตามมา

> **ห้ามขอให้ครูป้อนข้อมูล ต้องดักเก็บข้อมูลจากงานที่ครูทำอยู่แล้ว**

ครูตรวจงานนักเรียนอยู่แล้วทุกสัปดาห์ นั่นคือจุดที่ข้อมูลการเรียนรู้ถูกสร้างขึ้นจริงและถูกทิ้งไปทุกครั้ง เราไม่ได้ขอให้ครูทำงานเพิ่ม เราขอให้ครูถ่ายรูปกองงานก่อนตรวจ แล้วระบบคืนสามอย่างกลับไป: ผลตรวจร่าง กลุ่มปัญหาของห้อง และหลักฐาน PA

นี่คือความต่างจาก V2 เดิม V2 แก้ปัญหาภาระด้วยนโยบาย (เอาไปใช้กับ PA ได้นะ) เวอร์ชันนี้แก้ด้วยสถาปัตยกรรม (ไม่มีขั้นตอนป้อนข้อมูลตั้งแต่แรก)

---

## ภาพรวม pipeline

```
[ครูถ่ายรูปกองงาน 30 แผ่น]
        │
        ▼
 S0  Capture & Normalize        OpenCV: crop, deskew, homography
        │
        ▼
 S1  Student ID Resolution      closed-set match กับ roster 30 ชื่อ
        │
        ▼
 S2  Item Segmentation          ArUco registration หรือ layout model
        │
        ├──── Tier A: ปรนัย/ช่องกา ──────► mark detection (ไม่ใช้ VLM)
        ├──── Tier B: ตัวเลข/คำตอบสั้น ──► Typhoon OCR 1.5 + confidence
        └──── Tier C: การแสดงวิธีทำ ─────► VLM (low-confidence เสมอ)
        │
        ▼
 S3  Misconception Classification    closed-set เทียบ codebook ต่อ ตัวชี้วัด
        │
        ▼
 S4  Confidence Gate  ────────────► [คิวให้ครูยืนยัน] ──► labeled data
        │ (ผ่าน threshold)
        ▼
 S5  Classroom Aggregation      จัดกลุ่มตาม misconception ID ไม่ใช่ตามคะแนน
        │
        ▼
 S6  Method Retrieval           misconception ID → method ID (mapping ที่คนคัด)
        │
        ▼
 S7  Follow-up Loop             วัดซ้ำบน ตัวชี้วัด เดิม เทียบ before/after
        │
        ▼
 S8  PA Export                  PDF หลักฐาน ด้านที่ 2 ข้อ 2
```

## รายละเอียดแต่ละชั้น และจุดที่มันพัง

### S1 การระบุตัวนักเรียน

**ปัญหา:** OCR ลายมือชื่อไทยแม่นยำต่ำ

**วิธีแก้:** ไม่ต้องอ่านให้ถูก ต้องจับคู่ให้ถูก ห้องเรียนมีนักเรียน 30 คน ชื่อทั้ง 30 อยู่ในระบบแล้ว ปัญหาจึงเปลี่ยนจาก open-set transcription เป็น **closed-set matching** ใช้ Levenshtein distance บนผลอ่านที่ผิดบางส่วนเทียบกับรายชื่อ 30 ชื่อ ต่อให้อ่านผิด 3 ตัวอักษรก็ยังจับคู่ถูก เพราะไม่มีชื่ออื่นให้สับสน

ถ้าระยะห่างของอันดับ 1 กับอันดับ 2 น้อยเกินไป ให้ส่งเข้าคิวยืนยัน ไม่เดา

นี่คือหลักการที่ใช้ซ้ำทั้งระบบ: **แปลงปัญหา generation เป็นปัญหา classification เมื่อไรก็ตามที่ทำได้**

### S2 การตัดข้อ

สองเส้นทาง เลือกตามความพร้อม

| เส้นทาง | วิธี | ความน่าเชื่อถือ | ใช้เมื่อ |
|---|---|---|---|
| **A: ใบงานของระบบ** | พิมพ์ ArUco marker 4 มุม แล้ว register ภาพ ตำแหน่งทุกข้อรู้ล่วงหน้า | สูงมาก | เดโมและ POC |
| **B: ใบงานของครูเอง** | layout detection model | ต่ำกว่ามาก | roadmap |

**ให้เดโมด้วยเส้นทาง A และพูดตรงๆ ว่าเส้นทาง B ยังไม่พร้อม** ถ้าเคลมว่าถ่ายกระดาษอะไรก็ได้แล้วอ่านออก กรรมการที่เคยทำ CV จะรู้ทันทีว่าไม่จริง

เส้นทาง A ยังมีข้อดีทางธุรกิจ: ครูดาวน์โหลดใบงานจากคลังของเรา ซึ่งผูกกับ ตัวชี้วัด อยู่แล้ว แปลว่าเรารู้ตั้งแต่ก่อนถ่ายว่าข้อนี้วัดอะไร

### S3 การจำแนก misconception คือหัวใจ

**ทำไมไม่ให้ LLM บรรยายอิสระว่านักเรียนผิดตรงไหน**

เพราะ LLM เป็น labeler ที่ไม่คงเส้นคงวา ความผิดพลาดเดียวกันจะถูกบรรยายคนละคำในแต่ละครั้ง พอบรรยายคนละคำก็นับรวมไม่ได้ พอนับรวมไม่ได้ก็บอกไม่ได้ว่า "ห้องนี้มี 11 คนติดปัญหาเดียวกัน" ซึ่งเป็น output ที่มีค่าที่สุดของทั้งระบบ

**วิธีที่ใช้:** codebook ที่มี ID คงที่

```
M-FRAC-03
  ชื่อ:      เทียบเศษส่วนโดยดูตัวส่วนอย่างเดียว
  ตัวชี้วัด:  ค 1.1 ป.5/2
  ตัวอย่าง:  ตอบว่า 1/8 > 1/3 เพราะ 8 > 3
  วิธีสอนที่ผูกไว้: T-012, T-031
```

การจำแนกทำแบบนี้: retrieve เฉพาะ codebook entries ที่ผูกกับ ตัวชี้วัด ของข้อนั้น (ปกติ 3-8 รายการ) แล้วให้โมเดลเลือก 1 ใน N หรือตอบ "อื่นๆ" เป็น **closed-set classification** ซึ่งวัดผลได้ ทำซ้ำได้ และ prompt สั้นกว่ามาก

**taxonomy โตอย่างไรโดยไม่เพี้ยน:** ข้อที่ตกลงช่อง "อื่นๆ" จะถูก embed แล้ว cluster ไว้ เมื่อ cluster ไหนโตถึงเกณฑ์ จะถูกเสนอให้คนตรวจรับรองเป็น entry ใหม่ ระบบไม่สร้าง ID เองโดยไม่มีคนดู เพราะถ้าปล่อยให้สร้างเอง taxonomy จะแตกเป็นพันรายการภายในหนึ่งเทอมและกลับไปนับรวมไม่ได้เหมือนเดิม

### S4 ประตูความเชื่อมั่น และตัวเลขที่ควรเคลม

**อย่าเคลมว่า "OCR แม่น 95%"** ตัวเลขที่มีอยู่จริงไม่ได้สนับสนุน

Typhoon OCR 1.5 (2B) บน ThaiOCRBench:

| ประเภทเอกสาร | BLEU | ROUGE-L |
|---|---:|---:|
| เฉลี่ยรวม | 0.644 | 0.774 |
| **แบบฟอร์มลายมือ** | **0.522** | **0.645** |

ลายมือคือหมวดที่อ่อนที่สุดของทุกโมเดล และ 0.522 ไม่พอสำหรับการตรวจอัตโนมัติแบบไม่มีคนดู แต่ตัวเลขนี้เทียบแล้วยังดีกว่า Gemini 2.5 Pro (0.605/0.743 เฉลี่ยรวม) และ GPT-5 (0.459/0.618) บนภาษาไทย และเป็นโมเดลเปิดขนาด 2B ที่ self-host ได้ ซึ่งสำคัญกับต้นทุนและ PDPA

**ตัวเลขที่ควรเคลมแทน:**

> **coverage at precision ≥ 0.95** = สัดส่วนของข้อที่ระบบจัดการได้เองโดยที่ความแม่นยำในกลุ่มนั้นไม่ต่ำกว่า 95%

ต่างกันตรงไหน "แม่น 95%" แปลว่ายอมให้ผิด 5% แบบสุ่ม ซึ่งครูเชื่อไม่ได้เลย ส่วน "coverage 70% ที่ precision 95%" แปลว่าอีก 30% ที่ระบบไม่มั่นใจถูกส่งให้ครูดู ครูจึงเหลืองานตรวจ 30% แทน 100% และงานที่เหลือคือส่วนที่ยากจริง

การพูดแบบหลังทำสองอย่างพร้อมกัน: ป้องกันตัวเองจากข้อจำกัดของ OCR และแสดงว่าทีมเข้าใจ human-in-the-loop design ไม่ใช่แค่เรียก API

**การ calibrate:** ใช้ temperature scaling บน validation set แล้วเลือก threshold จากกราฟ coverage-precision ไม่ใช่ตั้งค่าตายตัว

### S5 output ที่ระบบเดิมทำไม่ได้

SGS และ Q-Info เก็บ**คะแนน** ระบบเราเก็บ**สาเหตุ**

```
ป.5/1  ค 1.1 ป.5/2  วัดเมื่อ 12 ส.ค. 2569

M-FRAC-03  เทียบเศษส่วนดูตัวส่วนอย่างเดียว      11 คน  ███████████
M-FRAC-07  หาตัวส่วนร่วมแล้วลืมคูณตัวเศษ         6 คน  ██████
M-FRAC-01  บวกเศษกับเศษ ส่วนกับส่วน              3 คน  ███
ถูกต้อง                                          8 คน  ████████
```

ครูเห็นแบบนี้แล้วรู้ทันทีว่าต้องสอนซ่อมอะไร เห็นคะแนนเฉลี่ย 62% แล้วไม่รู้อะไรเลย

### S6 คลังวิธีสอน

**ไม่ใช่ RAG บนข้อความอิสระ** เป็น mapping แบบ many-to-many ที่คนคัดไว้

```
T-012
  ชื่อ:        แถบเศษส่วนเทียบความยาว
  แก้:         M-FRAC-01, M-FRAC-03
  ระดับหลักฐาน: ปานกลาง (อ้าง: <ระบุงานวิจัย>)
  เวลาเตรียม:   10 นาที
  อุปกรณ์:     กระดาษ กรรไกร
  ข้อจำกัด:    ใช้ไม่ได้กับเศษส่วนตัวส่วนใหญ่กว่า 12
```

LLM มีหน้าที่เดียว: ปรับวิธีที่ถูกดึงมาให้เข้ากับบริบทครูปุ๊ก (สอน 5 วิชา คละชั้น ไม่มีอุปกรณ์) **LLM ไม่ได้เป็นคนคิดวิธี** ถ้าปล่อยให้คิดเอง เราก็เป็นแค่ ChatGPT ที่มี prompt สวยกว่า

**ฟิลด์ "ระดับหลักฐาน" และ "ข้อจำกัด" คือสิ่งที่ ChatGPT ไม่มี** ChatGPT ไม่บอกว่าวิธีที่มันแนะนำมีหลักฐานหนุนแค่ไหนและใช้ไม่ได้เมื่อไร

### S7 การวัดผลย้อนกลับ และสิ่งที่อ้างไม่ได้

วัดซ้ำบน ตัวชี้วัด เดิมใน 2-3 สัปดาห์ เทียบอัตราการเกิด misconception ID เดิม

**นี่คือ within-classroom pre/post ไม่มีกลุ่มควบคุม** อ้างความเป็นเหตุเป็นผลไม่ได้ เพราะเด็กโตขึ้น ครูสอนอย่างอื่นด้วย เด็กอาจไปเรียนพิเศษ

ถ้อยคำที่ใช้ได้: "ครู N คนใช้วิธีนี้ และรายงานว่านักเรียนที่ติดปัญหานี้ลดลงจาก X เป็น Y"
ถ้อยคำที่ใช้ไม่ได้: "ระบบเพิ่มผลสัมฤทธิ์ Z%"

ในระยะยาว ถ้ามีครูใช้พอ จะทำ staggered rollout เพื่อประเมินเชิงสาเหตุได้ แต่ห้ามพูดเหมือนว่าทำได้แล้ว

### S8 การส่งออกหลักฐาน PA

ผลิต PDF ที่มี: ตัวชี้วัด ที่วัด วิธีวัด ผลก่อน วิธีสอนที่ใช้ ผลหลัง และภาพผลงานนักเรียนที่ปิดชื่อ

ตรงกับ ว.PA ด้านที่ 2 ข้อ 2 "การวัดและประเมินผล การบันทึกหลังสอน แบบประเมินต่างๆ ในรูปแบบไฟล์ PDF"

**ขอบเขตที่ต้องพูดให้ชัด:** ไม่ได้แทนคลิปวิดีโอ (ด้านที่ 2 ข้อ 1) และไม่ได้แทนด้านที่ 1 หรือ 3 เคลมเกินนี้แล้วครูที่เป็นกรรมการจะรู้ทันที

## PDPA และความเป็นส่วนตัว

ลายมือนักเรียนพร้อมชื่อคือข้อมูลส่วนบุคคล

- การจับคู่ชื่อกับ roster ทำ**บนเครื่อง** เซิร์ฟเวอร์เห็นแค่ student ID ที่สุ่มขึ้น
- ภาพที่เก็บถาวรถูกครอบชื่อออก
- ชั้นรวมข้อมูล (โรงเรียน เขต) เห็นเฉพาะค่ารวม ไม่เห็นรายคนและ**ไม่เห็นรายครู**
- หลักการที่ต้องเขียนในข้อเสนอ: **ระบบประเมินความเข้าใจของผู้เรียน ไม่ได้ประเมินประสิทธิภาพของครูรายบุคคล** ถ้าไม่ประกาศข้อนี้ ครูจะไม่กล้าใช้ เพราะกลัวข้อมูลย้อนกลับมาประเมินตัวเอง

## การทำงานออฟไลน์

โรงเรียนขนาดเล็กในพื้นที่ห่างไกลมีปัญหาสัญญาณจริง (ศธ. ระบุเองในเหตุผลที่ยกเลิกโครงการ OBEC Channel)

- ถ่ายและจัดคิวได้ออฟไลน์ ประมวลผลเมื่อมีสัญญาณ
- Tier A (ปรนัย/ช่องกา) รันบนเครื่องได้ ไม่ต้องต่อเน็ต ครูจึงได้ผลบางส่วนทันที
- โมเดล 2B quantized มีโอกาสรันบนมือถือระดับกลางได้ แต่**ยังไม่ได้ทดสอบ** ให้ใส่เป็น roadmap ไม่ใช่คำสัญญา

## ทำไมไม่ใช้ ChatGPT เฉยๆ

คำถามนี้ V1 ตอบไม่ได้ นี่คือคำตอบของเวอร์ชันนี้ เรียงจากแข็งไปอ่อน

1. **ID คงที่ทำให้นับได้** ChatGPT บรรยายความผิดพลาดเดียวกันคนละคำทุกครั้ง จึงบอกไม่ได้ว่า "11 คนติดปัญหาเดียวกัน" ซึ่งเป็นข้อมูลชิ้นเดียวที่ทำให้ครูตัดสินใจสอนซ่อมได้
2. **ความจำข้ามครั้ง** ChatGPT ไม่รู้ว่าเดือนพฤษภาคมห้องนี้เคยติดอะไร และวิธีที่ครูลองไปแล้วได้ผลหรือไม่
3. **ผูกกับหลักสูตร** output ต้องอ้างอิง ตัวชี้วัด จึงจะใช้เป็นหลักฐาน PA ได้ ChatGPT ไม่ได้ผูกกับ ตัวชี้วัด ของหลักสูตรแกนกลาง
4. **เศรษฐศาสตร์ของงานเป็นกอง** 30 แผ่น × 8 ข้อ = 240 การอนุมาน การแยก tier ทำให้ราว 70% ไม่ต้องผ่าน VLM เลย ถ้าส่งทุกข้อเข้า frontier model ต้นทุนต่อห้องต่อสัปดาห์จะไม่คุ้ม
5. **ระดับหลักฐานของวิธีสอน** ChatGPT ไม่บอกว่าวิธีที่แนะนำมีงานวิจัยหนุนแค่ไหนและใช้ไม่ได้เมื่อไร

**และต้องยอมรับตรงๆ ว่า:** ถ้าครูอยากได้คำอธิบายแนวคิดหนึ่งให้เด็กหนึ่งคน ChatGPT ทำได้ดีกว่าและฟรี เราไม่ได้แข่งตรงนั้น เราแข่งที่การนับ การจำ และการผูกกับระบบราชการ

การยอมรับข้อนี้บนสไลด์จะได้คะแนนมากกว่าการเลี่ยง เพราะกรรมการจะถามอยู่ดี

## แผนพิสูจน์ที่ทำได้จริง

ไม่ใช่ "สร้างระบบให้กระทรวง" แต่เป็นสิ่งที่วัดผลได้ในสเกลเล็ก

**เฟส 0 (ก่อนเดโม):** ทำ codebook ด้วยมือ 25-30 รายการ ครอบคลุม คณิตศาสตร์ ป.4-6 เศษส่วนและทศนิยม พร้อมวิธีสอนที่ผูกไว้และแหล่งอ้างอิงต่อรายการ

> **บนสไลด์ต้องเขียนว่า "คลังชุดแรก 25 รายการ คัดด้วยมือจากงานวิจัย"** ห้ามทำให้ดูเหมือนมีเป็นพัน ถ้ากรรมการถามว่ามีกี่รายการแล้วตอบไม่ได้ จะเสียมากกว่าที่ได้

**เฟส 1 (4 สัปดาห์):** เก็บใบงานจริง 300 แผ่นจาก 2-3 ห้องเรียน ให้ครูติดป้าย misconception ด้วยมือเป็น ground truth

**เฟส 2:** วัด 3 ตัว
- coverage at precision ≥ 0.95 แยกตาม tier
- Cohen's kappa ระหว่างป้ายของระบบกับป้ายของครู (วัดว่า codebook ใช้งานได้จริงไหม ไม่ใช่แค่โมเดลแม่น)
- เวลาที่ครูใช้ตรวจ 30 แผ่น ก่อนและหลัง

**เฟส 3:** ครู 5 คนใช้ต่อเนื่อง 1 เดือน วัดว่ากลับมาใช้ซ้ำกี่ครั้ง

ตัวชี้วัดที่สำคัญที่สุดคือ **การกลับมาใช้ซ้ำ** ไม่ใช่ความแม่นยำ ถ้าครูใช้ครั้งเดียวแล้วเลิก แม่นแค่ไหนก็ไม่มีความหมาย

## ความเสี่ยงทางเทคนิคที่ต้องเขียนในข้อเสนอ

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| ลายมือเด็ก ป.4 อ่านยากกว่าลายมือผู้ใหญ่ในเบนช์มาร์ก | ตัวเลข 0.522 อาจดีเกินจริง | ต้องเก็บ ground truth จากลายมือเด็กจริงในเฟส 1 ก่อนเคลมตัวเลขใดๆ |
