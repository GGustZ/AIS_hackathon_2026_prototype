### 5. ผูกคลังวิธีสอนกับความเข้าใจผิด

**ปัญหา** `DB4_teaching_methods_110.csv` มี 110 รายการ จัดหมวดและ match Bloom ครบ แต่ไม่มีแถวใดผูกกับความเข้าใจผิดเลย และช่อง `when_to_use` ว่างทุกแถว ระบบจึงเลือกวิธีอัตโนมัติไม่ได้ สภาพนี้คือรายชื่อวิธีสอน ไม่ใช่ระบบแนะนำ ซึ่งเป็นจุดที่กรรมการฝั่ง Technical จะถามก่อน

**สิ่งที่ทำ** สร้าง `data/DB4_methods_bound_draft.csv` 20 แถว คัดจาก 110 รายการเดิม ทุกแถวกรอกครบสี่ช่องที่เคยว่าง

|---|---|
| `addresses_misc` | ผูกวิธีกับความเข้าใจผิด ถ้าไม่มี ระบบเลือกไม่ได้ |

| `not_suitable_when` | ข้อจำกัดที่พูดตรงๆ คือแถวที่ ChatGPT ไม่มี |

**กฎการเลือกที่ฝังอยู่ในข้อมูล ไม่ได้ซ่อนในโค้ด**

1. `persistence` เป็นตัวกำหนดชนิดของวิธี ทนสูงต้องใช้วิธีสร้างความขัดแย้ง ทนปานกลางหรือต่ำใช้การสอนซ้ำให้ชัดพอ จึงกำหนดให้ T-EI-01 กับ T-CCH-01 เป็น `incompatible_with` กัน
2. `plan_stage` เป็นตัวบอกตำแหน่งแทรก
3. `duration_min` กรองกับความยาวคาบจาก `teacher_profile` แผนตัวอย่างเป็นคาบ 50 นาที เหลือว่าง 25 นาที
4. `requires_lab` กับ `materials` กรองกับ `constraint_profile` ที่นับจากเหตุผลการปฏิเสธ
5. แถวที่ `plan_stage` เป็น ทั้งแผน (P-INQ-02, P-PHEN-02) ห้ามเสนอเป็นการแทรกในแผนที่เขียนเสร็จแล้ว เพราะการรับหมายถึงรื้อทั้งแผน ซึ่งขัดกับข้อห้ามเรื่อง diff

**สถานะ** ทุกแถวเป็น `draft` เพราะยังไม่มีการอ้างอิงงานวิจัยรายรายการ ช่อง `evidence_note` เขียนข้อจำกัดไว้รายแถว เช่น ฐานงานวิจัย conceptual change เป็นบริบทตะวันตกและยังไม่มีการทดสอบซ้ำในไทย ช่องนี้เป็นตัวแทนชั่วคราวของ `DB5.thai_context_note` จนกว่าจะสร้าง DB5 จริง

### 8. สร้างต้นแบบที่ทำงานได้จริง

เดโมเดิม (`prototype/mock.html` ชื่อเดิม `index.html`) เป็นค่าคงที่ในไฟล์ทั้งสามส่วน คือแผน ข้อค้นพบ และการตัดสินใจ
ต้นแบบใหม่ที่ `prototype/index.html` อ่านไฟล์จริง เทียบคลังจริง และบันทึกจริง

**เทคโนโลยี** ไม่มี dependency เลย ไม่มี framework ไม่มี bundler ไม่มี CDN
เป็น HTML CSS JavaScript ธรรมดา วางบน GitHub Pages ได้ทันที เหตุผลรายข้ออยู่ใน `docs/design/tech-stack.md`

**เปลี่ยนการตัดสินใจกลางทาง** เดิมวางแผนฝังข้อมูลลงไฟล์เดียวด้วยขั้นตอน build
เมื่อเป้าหมายเปลี่ยนเป็นเผยแพร่บน GitHub Pages ซึ่งเสิร์ฟผ่าน https อยู่แล้ว `fetch` ทำงานได้
จึงตัดขั้นตอน build ทิ้ง และให้ CSV ใน `data/` เป็นแหล่งความจริงที่โหลดตอนรัน ไม่มีข้อมูลซ้ำสองที่

**สิ่งที่ทำงานได้จริงแล้ว**

| ส่วน | สถานะ |

1. `DecompressionStream('deflate')` ปฏิเสธสตรีมที่มีไบต์ขึ้นบรรทัดใหม่ต่อท้าย ขณะที่ zlib ของ Node ยอม
   ผลคือสกัด PDF ไม่ได้เลยแม้แต่ตัวเดียว แก้โดยตัดไบต์ท้ายทิ้งก่อน inflate
2. การตรวจว่าฟอนต์ทำตัวอักษรใดหาย ใช้เกณฑ์ "ไม่มีเลย" ไม่ได้ เพราะเอกสารมีหลายฟอนต์
   ห ปรากฏ 8 ครั้งจากตัวอักษรไทย 13,600 ตัว ต้องใช้เกณฑ์อัตราส่วนแทน
3. สระ ำ ถูกแยกเป็นสองตัวใน PDF และครึ่งแรกมักไม่มีในตาราง `สำรวจ` จึงออกมาเป็น ` ารวจ`
   ต้องแปลง ำ เป็น า และตัดช่องว่างก่อนเทียบ
4. **การเทียบกับข้อความทั้งขั้นทำให้ทุกความเข้าใจผิดเข้าเกณฑ์หมด** เพราะข้อความยิ่งยาว
   ยิ่งมี n-gram ครบโดยบังเอิญ แก้โดยตัดเป็นประโยคก่อนเทียบ ได้ผลพลอยได้คือได้ประโยคที่ยกมาให้ครูดูพอดี

**สิ่งที่ยังไม่ได้ทำในรอบนี้ตามที่ตกลง**

- ไม่ได้เขียนข้อวัด 18 ข้อ ระบบจึงไม่แสดงชุดข้อวัด และบอกตรงๆ ว่าคลังยังไม่พร้อม ตาม FR-H-05
- ไม่ได้สร้างแผนตัวอย่างสังเคราะห์ คลังนี้จึงไม่มีไฟล์ทดสอบที่ commit ได้
  ต้องอัปโหลดแผนจริงของตัวเองเพื่อทดลอง
- ทางเข้าแบบยังไม่มีแผน (FR-J) ยังไม่ได้ทำเต็ม มีเฉพาะทางเลือกเลือกตัวชี้วัดเมื่ออ่านไฟล์ไม่ได้

**ข้อจำกัดที่ต้องพูดตรงๆ** การระบุว่าเป็นความเข้าใจผิดข้อไหนยังหยาบ
ระบบหาประโยคที่เข้าข่ายได้จริง แต่เมื่อความเข้าใจผิดสองข้อใกล้เคียงกัน คะแนนสูสีและอาจติดป้ายผิดข้อ
ประโยคที่ยกมาถูกต้อง แต่ป้ายกำกับอาจสลับกันได้ และยังทดสอบกับแผนจริงเพียงฉบับเดียว

### 9. เพิ่มทางเข้าแบบยังไม่มีแผน และเอาสวิตช์มุมมองออก

**หน้าเลือกเรื่องที่จะสอน** เดิมทำไว้แค่ทางเลือกเลือกตัวชี้วัดตอนอ่านไฟล์ไม่ได้ ยังไม่ใช่ FR-J เต็ม
ตอนนี้มีหน้าเต็มแล้ว เลือกชั้น 12 ระดับ มาตรฐาน 10 ตัว ติ๊กปัญหาที่เจอในห้อง 26 ข้อ และระดับ Bloom 6 ระดับ

**ตัวเลือกทั้งหมดอ่านจาก CSV ไม่ได้พิมพ์ซ้ำในโค้ด** `FORM_frontend_options.csv`
ถูกแยกเป็นบล็อกตามบรรทัดว่าง แล้วอ่านหัวข้อของแต่ละบล็อกเป็นชื่อชุดตัวเลือก

**สร้าง `data/FORM_problem_method_map.csv`** ด้วย `tools/derive-problems.mjs`
ปัญหา 26 ข้อในฟอร์มตรงกับคอลัมน์ "เหมาะกับปัญหา" ของ 26 กลยุทธ์ในคลัง 110 แถวพอดี
สคริปต์จึงอ่านสเปรดชีต เติมค่าจากเซลล์ที่ผสานไว้ แล้วเขียนเป็นตารางแบน ไม่ได้เขียนเนื้อหาขึ้นใหม่
ผลคือผูกกับวิธีที่กรอกรายละเอียดครบแล้ว 9 จาก 26 อีก 17 ข้อระบบแสดงชื่อกลยุทธ์
พร้อมบอกตรงๆ ว่ายังไม่ได้กรอกขั้นตอน เวลา และข้อจำกัด

ความเข้าใจผิดของหน่วยนั้นถูกวางไว้**บนสุด**ของผลลัพธ์เสมอ ตาม FR-J-03
และเมื่อเลือกมาตรฐานที่คลังยังไม่ครอบ ระบบบอกตรงๆ ว่ายังบอกไม่ได้ว่าเด็กมักติดตรงไหน ตาม FR-L-02

**เอาสวิตช์มุมมองครู/มุมมองเทคนิคออกจากมุมขวาบน** ตามที่สั่ง
มุมมองเทคนิคยังอยู่ แต่เรียกด้วยการต่อท้าย URL ด้วย `#tech`
เหตุผลที่ไม่ลบทิ้ง คือมันคือสิ่งที่ใช้ตอบกรรมการว่าคำแนะนำมาจากตารางไหนและกฎอะไร
แต่ไม่ควรเป็นปุ่มให้ครูที่กำลังใช้งานเห็น

**เพิ่มตัวจับเวลาและตัวตัดรอบตอนอ่านไฟล์** เดิมหน้าจอค้างอยู่ที่ "กำลังอ่าน" โดยไม่บอกอะไรเลย
ตอนนี้แสดงวินาทีที่ผ่านไป และถ้าเกิน 25 วินาทีจะเลิกอ่านแล้วพาไปทางเลือกเลือกจากหลักสูตรแทน
เดโมที่ค้างโดยไม่บอกอะไรคือความเสี่ยงที่ยอมไม่ได้

**พบบั๊กระหว่างทาง** ตัวอ่าน CSV ตัดแถวว่างทิ้ง ซึ่งถูกสำหรับตารางข้อมูล
แต่ผิดสำหรับ `FORM_frontend_options.csv` ที่ใช้แถวว่างเป็นตัวแบ่งบล็อก
ผลคือได้ระดับชั้น 79 รายการและ Bloom ศูนย์รายการ แก้โดยเพิ่มตัวเลือก `keepBlank`
