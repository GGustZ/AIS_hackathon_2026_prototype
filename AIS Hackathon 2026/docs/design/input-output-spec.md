# Input / Output Spec

สถานะ ณ 13 ส.ค. 2569 หลังการตัดสินใจสามข้อ: ตัดการวัดท้ายคาบออกจากเฟส 1, เปลี่ยนจุดตั้งต้นเป็นการอัปโหลดแผนการสอนเดิมของครู, และปรับโครงฐานข้อมูลจาก D1-D7 เดิม

**ประโยคเดียว:** ครูอัปโหลดแผนการสอนที่เขียนไว้แล้ว ระบบบอกว่าแผนนี้ยังไม่ดักจุดที่นักเรียนมักเข้าใจผิดตรงไหน และเสนอสิ่งที่จะแทรกเข้าไป

# ส่วนที่ 1: INPUT

## หลักการที่ห้ามละเมิด

> ไม่มีช่องพิมพ์ในเส้นทางหลัก ทุกอย่างเป็นการอัปโหลด การเลือก หรือการแตะ

## 1.1 ติดตั้งครั้งแรก

| ครูทำ | รูปแบบ | เวลา |
|---|---|---|
| อัปโหลดแผนการสอน 1 ไฟล์ | .docx หรือ .pdf | 20 วินาที |

ไม่มีหน้าฟอร์ม ไม่มีการสมัครที่ต้องกรอกโรงเรียน ไม่มีรายชื่อนักเรียน

**ระบบสกัดจากไฟล์เอง** (แบบฟอร์มแผนการจัดการเรียนรู้ไทยมีช่องเหล่านี้เป็นมาตรฐาน)

```
plan_document {
  หน่วยการเรียนรู้        → ชื่อหน่วย, แผนที่เท่าไร
  กลุ่มสาระ / รายวิชา / ชั้น
  เวลา                    → จำนวนคาบ, นาทีต่อคาบ
  มาตรฐาน / ตัวชี้วัด      → รหัส เช่น ว 2.2 ป.5/1     ← กุญแจหลัก
  สาระสำคัญ
  จุดประสงค์การเรียนรู้    → แยก K / P / A
  สาระการเรียนรู้
  กิจกรรมการเรียนรู้       → ขั้นนำ / ขั้นสอน / ขั้นสรุป
  สื่อและแหล่งเรียนรู้      → ใช้อนุมานข้อจำกัดด้านอุปกรณ์
  การวัดและประเมินผล      → วิธีวัด, เครื่องมือ, เกณฑ์
  บันทึกหลังสอน           → ถ้ามี
}
```

**ช่อง `ตัวชี้วัด` คือกุญแจ** ทุกอย่างต่อจากนี้แขวนอยู่กับรหัสนั้น และแบบฟอร์มไทยเกือบทุกฉบับมีช่องนี้อยู่หัวกระดาษ จึงไม่ต้องเดา

**ถ้าสกัดตัวชี้วัดไม่ได้** ระบบถามครั้งเดียว: เลือก ชั้น → หนังสือเรียน → บท แล้ว map เป็นรหัสภายใน ครูไม่เห็นรหัสเลย

## 1.2 ทุกครั้งที่ใช้งาน

| ครูทำ | รูปแบบ |
|---|---|
| อัปโหลดแผนที่กำลังจะสอน | 1 ไฟล์ |
| **หรือ** เลือก ชั้น → หนังสือ → บท (กรณีไม่มีแผน) | 1 การเลือก |

## 1.3 การตัดสินใจ

ทุกอย่างเป็นการแตะ ไม่มีการพิมพ์

| ปุ่ม | ผล |
|---|---|
| แทรก | ใส่ข้อเสนอลงในแผน ณ ตำแหน่งที่ระบุ |
| ขอแบบอื่น | เสนอ variant อื่นของวิธีสอนเดียวกัน |
| ไม่เอา | เก็บเหตุผลจากตัวเลือกปิด |

**เหตุผลที่ไม่เอา เป็นตัวเลือกปิดเท่านั้น** ห้าม free text เพราะวิเคราะห์ย้อนหลังไม่ได้

```
[ ] เวลาไม่พอ
[ ] ไม่มีอุปกรณ์
[ ] ไม่เหมาะกับห้องนี้
[ ] ไม่เห็นด้วยกับวิธีนี้
[ ] อื่นๆ
```

## 1.4 ไม่บังคับ กรอกเมื่ออยาก

| ครูทำ | ได้อะไรกลับ |
|---|---|
| ชั้น + วิชา + คาบต่อสัปดาห์ | ระบบสร้างตารางภาระงานใน **PA1 ส่วนที่ 1 ข้อ 1.1** ให้ ซึ่งเป็นส่วนที่กรอกหนักที่สุดของเอกสาร PA |

นี่คือช่องเดียวที่ครูพิมพ์ และมันจ่ายคืนตัวเองทันที

## 1.5 ตัดออกจากเฟส 1 แล้ว

ต้องยังคงอยู่ในไดอะแกรมพร้อมป้าย "เฟส 2 ยังไม่ได้สร้าง" ห้ามลบทิ้ง

- การถ่ายภาพห้องตอนนักเรียนยกการ์ดตอบ
- การถ่ายกองงานที่ตรวจแล้ว
- รายชื่อนักเรียน
- การวัดผลก่อน-หลัง

# ส่วนที่ 2: โครงฐานข้อมูล

## 2.1 หลักการตรวจสอบทุกตาราง

ทุกตารางต้องตอบสามคำถามได้ ถ้าตอบไม่ได้ข้อใดข้อหนึ่ง ให้ตัดหรือรวมเข้ากับตารางอื่น

> **ใครเขียน / ใครอ่าน / ตอนนี้มีกี่แถว**

ตารางที่ไม่มีทั้งคนเขียนและคนอ่าน ทำให้ทั้งไดอะแกรมเสียความน่าเชื่อถือ **7 ตารางที่มี 2 ตารางว่างและ 1 ตารางไม่มีใครอ่าน ดูแย่กว่า 6 ตารางที่มีของครบ**

## 2.2 ตารางในเฟส 1

แบ่งเป็นสองกลุ่มตามว่าใครเป็นคนใส่ข้อมูล

**กลุ่ม ก คลังอ้างอิง** สร้างล่วงหน้า อ่านอย่างเดียวตอนใช้งาน

| # | ตาราง | เก็บอะไร | ใครเขียน | ใครอ่าน | สถานะตอนนี้ |
|---|---|---|---|---|---|
| **DB1** | CURR หลักสูตรและตัวชี้วัด | ตัวชี้วัด รหัส สาระการเรียนรู้แกนกลาง ลำดับก่อนหลังระหว่างชั้น | สกัดจาก PDF หลักสูตร ครั้งเดียว | ตัวเปรียบเทียบ 1 | ต้องสกัด |
| **DB2** | MISC **คลังความเข้าใจผิด** | ID คงที่ อาการ ตัวลวง ความถี่ ความทนต่อการสอน | ทีมเขียน + คนตรวจรับรอง | ตัวเปรียบเทียบ 2, DB6 | **ศูนย์แถว** |
| **DB3** | MAP ตารางเชื่อม | `(misconception_id, ตัวชี้วัด_code, curriculum_version)` | ทีมเขียน | ตัวเปรียบเทียบ 2 | ยังไม่มี |
| **DB4** | METHOD คลังวิธีสอน | 4 หมวด 110 รายการ ขั้นตอน เวลา อุปกรณ์ ข้อจำกัด compatibility | ทีมเขียน | ตัวสร้างข้อเสนอ | มีโครง 110 แถว คอลัมน์ "ใช้เมื่อ" **ว่างทุกแถว** |
| **DB5** | EVID หลักฐานงานวิจัย | งานวิจัย ประชากร คุณภาพ ข้อจำกัด เชื่อมกับ DB2 และ DB4 แบบ many-to-many | ทีมเขียนตอนสร้าง | หน้าจอ 2 | ยังไม่มี |
| **DB6** | ITEM คลังข้อวัด | ข้อวัด ตัวลวงผูกกับ misconception_id เกณฑ์ผ่าน | ทีมเขียน | หน้าจอ 4 | ยังไม่มี |

**กลุ่ม ข ข้อมูลที่เกิดจากการใช้งาน** เขียนตอนรัน

| # | ตาราง | เก็บอะไร | ใครเขียน | ใครอ่าน | สถานะตอนนี้ |
|---|---|---|---|---|---|
| **DB7** | PLAN แผนที่แยกโครงแล้ว | ทุกฟิลด์ตามหัวข้อ 1.1 | P0 ตัวแยกโครงแผน | ตัวเปรียบเทียบทั้ง 3 | ยังไม่มี |
| **DB8** | HIST ประวัติและการตัดสินใจ | แผนที่ครูเคยอัปโหลด สิ่งที่รับ สิ่งที่ปฏิเสธ + เหตุผล | ทุกครั้งที่ครูแตะ | ตัวเปรียบเทียบ 3 | โตเอง |

การแบ่งสองกลุ่มนี้ตอบคำถามที่กรรมการจะถามไปในตัว: กลุ่ม ก คือสิ่งที่ทีมต้องสร้างก่อนเปิดใช้ กลุ่ม ข คือสิ่งที่โตเองเมื่อมีผู้ใช้ **และ DB2 คือตารางเดียวในกลุ่ม ก ที่ไม่มีใครแจกให้**

**ไม่ต้องเป็นตาราง**

- **Taxonomy (Bloom / DOK / PISA)** ทำเป็นไฟล์อ้างอิงคงที่ ไม่มีใครเขียน ไม่เคยเปลี่ยน การทำให้เป็น DB ทำให้ดูเหมือนมีของมากกว่าความจริง ใช้เป็นชั้นเทียบระดับความยากของข้อวัด ไม่ใช่ชั้นวินิจฉัย
- **Teacher Profile** เป็น view คำนวณจาก HIST ไม่ใช่ตารางให้กรอก เพราะบริบทครูเกือบทั้งหมด (วิชา ระดับชั้น โรงเรียน ความละเอียดที่เขียน กิจกรรมที่ใช้จริง ความยาวคาบ) อนุมานได้จากแผนที่อัปโหลดมาแล้ว

## 2.3 ตารางในเฟส 2 วาดไว้ ติดป้าย ยังไม่สร้าง

| ตาราง | เก็บอะไร | ทำไมยังไม่มีในเฟส 1 |
|---|---|---|
| CLASS | ข้อมูลรายห้อง ทรัพยากร ข้อจำกัด | เฟส 1 ไม่มี entity ชื่อห้องเรียน เพราะตัดรายชื่อและการวัดออก ส่วนทรัพยากรกับเวลาอยู่ในตัวแผนอยู่แล้ว |
| RESULT | ผลการวัดก่อน-หลัง | ไม่มีการเก็บผลในเฟส 1 |

## 2.4 การเทียบกับโครง D1-D7 เดิม

| เดิม | ใหม่ | เปลี่ยนอะไร |
|---|---|---|
| D1 Teacher Profile | **VIEW teacher_profile** | จากตารางให้กรอก เป็นค่าที่คำนวณจาก DB7 + DB8 |
| D2 Class DB | **เลื่อนไปเฟส 2 (DB9)** | เฟส 1 ไม่มีห้องเรียนเป็น entity ฟิลด์ย้ายเข้า DB7 |
| D3 Standard & Guideline | **DB1 CURR + DB3 MAP** | เพิ่มตารางเชื่อมพร้อม `curriculum_version` |
| D4 Problem & Skill | **ผ่าเป็น DB2 MISC + REF taxonomy.json** | ของสองชนิดที่ต่างกันสิ้นเชิง อยู่ตารางเดียวกันไม่ได้ |
| D5 Orchestration | **DB4 METHOD** | เหมือนเดิม |
| D6 Support Evidence | **DB5 EVID** | ทำเป็น many-to-many และย้ำว่ากรอกตอนสร้าง ไม่ใช่ดึงสดตอนรัน |
| D7 Runtime Data | **DB8 HIST** | เดิมเขียนอย่างเดียวไม่มีใครอ่าน ตอนนี้เป็นตัวเปรียบเทียบที่ 3 |
| (ไม่มี) | **DB6 ITEM** | ถ้าไม่มี ระบบสร้างข้อวัดใหม่ทุกครั้งแบบไม่คงเส้นคงวา เฟส 2 จะเทียบผลข้ามครั้งไม่ได้ |
| (ไม่มี) | **DB7 PLAN** | สิ่งของหลักของทั้งโปรดักต์ โครงเดิมไม่มีตารางเก็บ |

**นอกตาราง**

| | คืออะไร | ทำไมไม่นับเป็น DB |
|---|---|---|
| `REF taxonomy.json` | Bloom, DOK, PISA | ไม่มีใครเขียน ไม่เคยเปลี่ยน อ่านอย่างเดียว |
| `VIEW teacher_profile` | บริบทครู | คำนวณจาก DB7 + DB8 ไม่ได้เก็บซ้ำ |

**เฟส 2 วาดไว้ ติดป้าย ยังไม่สร้าง**

| # | ตาราง | เก็บอะไร |
|---|---|---|
| DB9 | CLASS | ข้อมูลรายห้อง ทรัพยากร ข้อจำกัด |
| DB10 | RESULT | ผลการวัดก่อน-หลัง |

## 2.5 เหตุผลที่ต้องผ่า D4

| | MISC คลังความเข้าใจผิด | Taxonomy |
|---|---|---|
| ที่มา | ทีมเขียนเอง | ตำรา สาธารณะ |
| เปลี่ยนบ่อยไหม | โตทุกเดือน | ไม่เปลี่ยนเลย |
| ใครรับรอง | คนตรวจ | ไม่มีใคร |
| มูลค่า | **ทรัพย์สินชิ้นเดียวของโปรดักต์** | ศูนย์ |

การเอาสองอันใส่ตารางเดียวกัน ทำให้ของที่เป็นทรัพย์สินหายไปในกอง แยกออกมาแล้วจะชัดบนสไลด์ว่าอะไรคือสิ่งที่ทีมสร้าง

**และคำว่า "กฎตรวจหา" ต้องเขียนใหม่** เฟส 1 ไม่ได้ตรวจจากคำตอบนักเรียน แต่ตรวจช่องว่างในแผน กฎจึงไม่ใช่ "ถ้าเด็กตอบ ค แปลว่าติด M-01" แต่เป็น **"ถ้าแผนไม่มีขั้นที่จัดการ M-01 ให้แจ้ง"**

## 2.6 โครงหนึ่งแถวของ MISC

```
M-FORCE-01
  ชื่อ         วัตถุที่หยุดนิ่งแปลว่าไม่มีแรงกระทำ
  ตัวชี้วัด     ว 2.2 ป.5/1        (ผ่านตาราง MAP)
  อาการ       ตอบว่าหนังสือวางบนโต๊ะไม่มีแรงกระทำ
              วาดแผนภาพแรงแล้วไม่มีลูกศรเลย
  ตัวลวง      "ไม่มีแรงกระทำเพราะวัตถุไม่เคลื่อนที่"
  ความถี่     สูง
  แก้ด้วย     T-CC-01 (Cognitive Conflict), T-EX-03
  หลักฐาน    ผ่านตาราง EVID
  ข้อจำกัด    ต้องมีวัสดุให้เด็กกดทดลอง ใช้เวลา 10 นาที
```

**ตาราง MAP ต้องแยกจาก MISC** เพราะ สพฐ. นำร่องหลักสูตรฐานสมรรถนะใน ป.4-6 ปีการศึกษานี้ พอหลักสูตรเปลี่ยน เขียน MAP ชุดใหม่ โดยไม่ทิ้ง MISC และ HIST

ความเข้าใจผิดเรื่องแรงไม่เปลี่ยนตามหลักสูตร สิ่งที่เปลี่ยนคือรหัสราชการ

# ส่วนที่ 3: OUTPUT

## 3.1 ตัวเปรียบเทียบ 3 ตัว รันหลังบ้าน

| # | เทียบ PLAN กับ | ตอบคำถาม | พร้อมใช้ |
|---|---|---|---|
| 1 | CURR | ครอบตัวชี้วัดครบไหม | ครั้งแรก |
| 2 | **MISC ผ่าน MAP** | **ดักจุดที่เด็กมักพังหรือยัง** | ครั้งแรก |
| 3 | HIST | ต่างจากที่คุณเคยทำตรงไหน | หลังอัปโหลด 3-5 ไฟล์ |

ตัวที่ 2 คือตัวที่คู่แข่งทำไม่ได้ ตัวที่ 1 และ 3 ทำได้แต่เกือบฟรีเมื่อแยกโครงแผนแล้ว

## 3.2 กฎการจัดอันดับ

รันสามตัว **แสดงไม่เกิน 3 รายการ** ที่เหลืออยู่หลังปุ่ม "ดูทั้งหมด"

จัดตาม**ความรุนแรง** ไม่ใช่ตามหมวด เพราะแผนที่ครูมีอยู่มักครอบตัวชี้วัดครบอยู่แล้ว ถ้ายิงเรื่องความครบทุกครั้งระบบจะดูจู้จี้

| ระดับ | เงื่อนไข |
|---|---|
| สูง | มีตัวชี้วัดที่แผนไม่ครอบเลย |
| สูง | ความเข้าใจผิดความถี่สูงของหน่วยนี้ ที่แผนไม่มีขั้นดักไว้ |
| กลาง | ความเข้าใจผิดความถี่รอง |
| กลาง | กิจกรรมที่ครูเคยใช้ประจำแล้วหายไปจากแผนนี้ |
| ต่ำ | ความต่างเชิงรูปแบบ ไม่ต้องแสดง |

## 3.3 หน้าจอ 1: ผลตรวจแผน

หน้าจอหลักของเดโม

# ส่วนที่ 4: พฤติกรรมตอนยังไม่มีข้อมูล

| สถานการณ์ | ระบบทำอะไร |
|---|---|
| อัปโหลดครั้งแรก | รันตัวเปรียบเทียบ 1 กับ 2 ไม่แสดงช่องว่างของตัวที่ 3 |
| สกัดตัวชี้วัดจากไฟล์ไม่ได้ | ถามครั้งเดียว: ชั้น → หนังสือ → บท |
| ตัวชี้วัดนี้ยังไม่มีใน MAP | บอกตรงๆ ว่า "หน่วยนี้ยังไม่อยู่ในคลังชุดแรก" แล้วให้ผลจากตัวเปรียบเทียบ 1 อย่างเดียว |
| ไฟล์อ่านไม่ออก | ให้เลือกจากหลักสูตรแทน ไม่ปล่อยให้ตัน |

แถวที่สามสำคัญ **อย่าให้ระบบเดาเมื่อไม่มีข้อมูล** การบอกว่าไม่รู้ได้ความเชื่อถือมากกว่าการแต่งคำตอบ
